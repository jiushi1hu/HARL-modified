## 1. 安全动作与生态可行性

新增 `examples/diagnose_cascade_feasibility.py`。读取一次完整日志，在独立环境中恢复每日动作。
回放核对日期、动作映射、完整安全路径、恢复模式、库容和原始违反量。
补充的运行检查还核对 cost 与 active flag，已在真实三日回放中验证。

诊断使用真实 SafetyRecoveryResult：

1. 原上游动作确定后的 conditional mask：是否有满足本库生态要求的动作。
2. 当前有效 S3 上下文中的完整联合路径：若允许改变上游动作，是否有满足本库生态要求的路径。
3. 五库同时满足生态要求：对节点加入生态条件后，重新求完整路径。
4. 最终 fallback 若强制单一路径，则只检查该路径；不能把所有 P1-safe 路径当成 Actor 可选动作。

完整路径节点必须同时具有前向可达性和后向可延拓性。
本工具只诊断，不修改生产 mask，不把生态要求移到 Layer 1。

## 2. 优势与 lambda 更新链路

读取并核对了实际 Runner 和 LagrangianManager：

- 更新前固定 lambda_snapshot，使用 A_L = A_R - sum(lambda_snapshot * A_C)。
- Critics 更新后没有重新计算这轮 Actor 的优势。
- lambda 在该轮 Actor 更新结束后更新。
- 历史日志第1至26轮逐轮复算与公式一致，最大差异约2.3e-10，属于浮点误差。

补充只读日志指标：

- reward_rms、reward_std：奖励优势幅度。
- constraint_rms、weighted_constraint_rms：每项约束优势及其乘lambda后的幅度。
- penalty_rms、penalty_std：各项有符号约束优势相加后的幅度。
- penalty_to_reward_rms：总约束项与奖励项的RMS比；奖励项为0时不伪造比例。
- sign_flip_fraction：扣除约束项后优势符号翻转的样本比例。
- lambda_snapshot：明确使用当前轮更新前的乘子。

日志会写入现有 TensorBoard，并在每轮终端打印主要幅度。
这些指标不是梯度范数；判断Actor实际响应仍需结合动作概率、mask和后续cost。
历史运行没有保存这些数值，不能回填为当时测量结果。新代码需新进程才能生效。

## 3. 折扣与预算

保留 gamma=0.99。1096日批次且约束全程生效时：

- 第一年权重97.4498%。
- 第二年权重2.4874%。
- 第三年权重0.06282%。

这符合用户本次明确的近期优先目标。仍保留全周期等权cost和年度统计，避免把折扣达标解释成每年都达标。

预算0.0001是实验阈值，不是工程合规依据。每库应分别校准：

- WDD目前无需为了让lambda非零而压低预算。
- BHT存在当日可避免违规，应先看策略响应。
- XLD/XJB需区分此前状态调度、当日安全约束与学习影响；目前未证明0.0001可达或不可达。
- THR初始确定性策略已经满足0.0001折扣预算，训练后却超标，故没有依据优先通过放宽THR预算解决问题。

本次维持已有预算、lambda学习率与训练轮数，避免在尚未测量优势强度时同时改多个实验因素。
后续预算校准应基于可行策略的多轮/多种子统计，并明确是折扣预算，不是缺水率或违规天数比例。

训练后末期多个水库库容更低，例如XLD从90.92亿m³降至51.16亿m³。
因此发电增益含不同末期蓄水状态的影响，不能直接解释为可持续效率提升。

结论：XLD固定策略有改善；XJB和THR没有达到长期约束优化预期。
训练随机轨迹与确定性评估口径不同，不能直接比较其cost大小来推断收敛。
此对照仅覆盖同一历史来水序列，不证明泛化或随机策略期望约束可行。
