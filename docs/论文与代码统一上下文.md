# 一、研究对象与总体目标

本研究面向五座串联梯级水库的多约束联合调度问题。

五库固定水力顺序为：

WDD（乌东德）
  ↓
BHT（白鹤滩）
  ↓
XLD（溪洛渡）
  ↓
XJB（向家坝）
  ↓
THR（三峡）

每座水库对应一个独立智能体，五个智能体分别拥有独立 Actor。

研究目标不是简单地最大化单日发电量，而是在保证当前时刻物理安全和长期运行约束的前提下，通过多智能体强化学习优化梯级联合调度策略。

整个方法分为两个层次：

第一层：当前时刻安全动作层
第二层：长期运行约束学习层

总体流程：

当前状态与当前来水
        ↓
第一层：安全动作构造
        ↓
S201 单库局部可行性
        ↓
S202 相邻水库动作兼容性
        ↓
S203 梯级后向可延拓性
        ↓
若联合可行集为空
        ↓
S3 分级最小松弛
        ↓
S4 按 WDD→BHT→XLD→XJB→THR 顺序采样
        ↓
执行联合动作
        ↓
水量平衡 / 水位 / 出力 / 发电量
        ↓
长期约束 cost
        ↓
第二层：HAPPO-Lagrangian
        ↓
Reward Critic
Constraint Critics
Lagrangian multipliers
        ↓
更新五个 Actor

# 二、时间尺度与基本水力关系

当前仿真采用日尺度：

Δt = 86400 s

仿真区间：

2023-01-01 ~ 2025-12-31

当前版本不显式考虑河道传播时滞。

因此下游水库当日总入流由直接上游当日实际下泄与本库区间入流构成：

\[ I_{i,t} = Q^{exec}_{i-1,t} + I^{int}_{i,t} \]

即：


BHT：
I_BHT,t = Q_WDD,t^exec + I_BHT,t^int

XLD：
I_XLD,t = Q_BHT,t^exec + I_XLD,t^int

XJB：
I_XJB,t = Q_XLD,t^exec + I_XJB,t^int

THR：
I_THR,t = Q_XJB,t^exec + I_THR,t^int

只有 WDD 使用外部上游总来水。

数据字段语义固定为：

WDD_external_inflow_m3s
BHT_interval_inflow_m3s
XLD_interval_inflow_m3s
XJB_interval_inflow_m3s
THR_interval_inflow_m3s


因此 BHT、XLD、XJB、THR 的输入数据不能预先被累加为“总入流”。

当前程序约定：

\[
Q^{exec}_{i,t}
=
Q^{tar}_{i,t}
\]

即 Actor 选择的候选总下泄就是当前真正执行的总下泄。

如果未来增加动作投影、裁剪、强制泄洪或二次修正机制，则必须同时修改：

```text
S202
SequentialSampler
CascadeReservoirEnv.step()
```

以保证候选动作兼容性与真实物理执行一致。

# 四、约束优先级 P1、P2、P3、P4

固定优先级：
P1 > P2 > P3 > P4
其中优先级越高，越不允许被破坏。

---

## 4.1 P1：绝对物理安全约束

P1 属于不可主动松弛的安全边界。

包括但不限于：

水量平衡
绝对最低物理水位
绝对最高安全水位
总下泄物理能力
机组/泄洪设备能力边界
其他不可突破的物理安全边界

如果以后显式实现紧急强制泄洪规则，则其触发后的强制动作也属于 P1 安全语义。

任何恢复机制都必须满足：
P1\ 始终成立

禁止通过扩大 P1 来恢复动作可行性。

---

## 4.2 P2：常规运行水位约束

P2 表示正常运行时应尽量严格满足的运行水位边界，例如：

```text
正常蓄水运行上限
汛限水位
蓄水期控制水位
消落期控制水位
其他阶段性运行水位
```

当前环境根据运行阶段选择 P2 水位上限。

P2 原则上不主动连续放宽。

只有当：

```text
P4 已经达到最大允许松弛
并且
P3 已经达到最大允许松弛
并且
完整五库联合可行集仍为空
```

时，才进入 P2 emergency fallback。

此时保持 P1 不变，并在所有 P1 安全的完整五库联合动作中选择：

\[
	ext{P2 归一化总违反量最小的联合动作}
\]

并记录该违反量。

---

## 4.3 P3：相邻时段变化约束

P3 当前包括：

相邻日水位变化限制
相邻日总下泄变化限制

当前工程配置：

```yaml
safety:
  p3:
    release_change_ratio: 0.5
    release_change_floor_m3s: 5000.0
    max_relaxation_factor: 2.0

    level_change_limit_m:
      WDD: 0.30
      BHT: 0.50
      XLD: 0.90
      XJB: 0.20
      THR: 1.40
```

正常下泄变化约束：

\[
|Q_t-Q_{t-1}|
\le
\max(
0.5Q_{t-1},
5000
)
\]

P3 松弛时，对该允许变化范围乘以 relaxation factor。

最大 relaxation factor：

```text
2.0
```

第一天没有可信的前一日实际下泄：

```text
previous_release_m3s = None
```

因此第一天只取消 P3 中的“下泄变化”子约束。

但是第一天当前水位是已知的，所以 P3 水位变化限制仍然有效。

不得人为生成首日前一天的下泄。

## 4.4 P4：枯水期下泄与入流关系约束

P4 主要在 `dry_supply` 阶段启用。

当前形式：

\[
Q^{tar}_{i,t}
\ge
eta_4 I_{i,t}
\]

当前配置：

```yaml
safety:
  p4:
    normal_release_inflow_ratio: 1.0
    min_release_inflow_ratio: 0.75
```

# 五、S201：单库局部可行性

对每座水库，在当前状态和给定入流下，判断每一个候选总下泄动作是否满足当前有效约束。

候选动作由 `ReleaseActionMapper` 提供。

动作映射：

action index
    ↓
normalized action
    ↓
candidate total release

当前为线性映射。

动作数由 YAML 决定，当前项目设计：

```yaml
action:
  num_actions: 201
```

程序中不能另外写死其他动作数。

单库水量平衡：

\[
V_{i,t+1} = V_{i,t} + (I_{i,t}-Q_{i,t})\Delta t
\]

S201 根据当前：

```text
storage
inflow
candidate release
当前生效的 P1
当前生效的 P2
当前生效的 P3
当前生效的 P4
```

计算候选动作 mask。

这里的固定原则是：

> S201 必须判断当前 `ConstraintContext` 中全部正在生效的 Layer-1 约束，而不是只判断 P1/P2/P3。

其中，P4 仅在其适用运行阶段（例如 `dry_supply`）生效；不生效时不参与当前候选动作筛选。

P4 不是“只有联合可行集为空以后才出现”的约束。正常模式下，只要 P4 在当前时段生效，就必须先按正常 P4 要求参与 S201/S202/S203 联合可行性判断；只有完整联合可行集为空时，S3 才允许按照规定范围对 P4 做最小必要松弛。

S201 本身不能进行任何约束松弛。正常模式使用正常约束参数；S3 负责生成恢复模式下的约束参数，再重新调用 S201/S202/S203 判断是否恢复完整联合可行路径。

# 六、S202：相邻水库动作兼容性

S202 用于描述相邻水库候选动作之间的条件兼容关系。

对于上游候选动作 \(a_i\)：

\[
Q^{tar}_{i,t}(a_i)
\]

下游候选入流为：

\[
I_{i+1,t}
=
Q^{tar}_{i,t}(a_i)
+
I^{int}_{i+1,t}
\]

然后重新计算下游在该候选入流下的 S201 可行 mask。

因此：

\[
C_{i,i+1}(a_i,a_{i+1})
\in
\{0,1\}
\]

表示：
上游选择 a_i 时
下游动作 a_{i+1}
是否局部可执行

注意：

S202 使用上游“候选目标下泄”，而不是 Actor 已经执行的真实动作。

因为此时还处在联合安全集合构造阶段。

# 七、S203：梯级后向可延拓性

仅有相邻兼容性仍然不够。

例如：

WDD 某动作自身可行
并且
存在一个 BHT 动作与之兼容

并不意味着该路径一定能继续延伸到 THR。

因此从最下游开始做后向递推：

THR
 ↑
XJB
 ↑
XLD
 ↑
BHT
 ↑
WDD

WDD 最终暴露给 Actor 的 root mask 必须满足：

WDD 本地可行
并且
存在 BHT 动作
并且
该 BHT 动作能够继续延伸到 XLD
并且
最终能够形成到 THR 的完整路径


因此：

\[
	ext{WDD 可选动作}
\Rightarrow
	ext{至少存在一条完整五库可执行联合动作}
\]

对于 BHT、XLD、XJB：


当前 mask
=
与已选直接上游动作兼容
AND
当前动作仍能向更下游延伸


对于 THR：


当前 mask
=
与已选 XJB 动作兼容

如果正常约束下：

\[
\mathcal A_t^{joint}
=
arnothing

# 九、S4：水力因果驱动的顺序多智能体决策

真实 Actor 采样顺序固定：


WDD
 ↓
BHT
 ↓
XLD
 ↓
XJB
 ↓
THR


不能同时并行采样五个 Actor。

WDD 首先根据：


WDD base observation
+
WDD root safe mask


选择动作。

得到 WDD 当前下泄后：

\[
I_{BHT,t}
=
Q^{exec}_{WDD,t}
+
I^{int}_{BHT,t}
\]

构造 BHT 真实 decision observation：

\[
o^{dec}_{BHT,t}
=
(
o^{base}_{BHT,t},
I_{BHT,t}
)
\]

同时根据 WDD 已选动作，从 `SafetyRecoveryResult` 获得 BHT 条件 mask。

之后 BHT Actor 才允许采样。

这一步体现论文中的一个核心思想：

> 串联梯级水库的多智能体动作不是同一时刻相互独立地产生，而是受到水力因果关系约束的顺序决策过程。

# 十二、行为轨迹与 ActorBuffer

由于下游 Actor 的真实 observation 和 mask 是在上游动作确定后才生成，因此不能完全沿用普通并行 MARL 的 buffer 写入方式。

对每个智能体、每个时间步 \(t\)，必须保存：

\[
(
o^{dec}_{i,t}, M_{i,t}, a_{i,t}, \log\pi^{old}_{i,t}
)
\]

并保证全部写在同一个 buffer index `t`。

不能发生：

action/log_prob 写在 t
observation/mask 写在 t+1

否则 HAPPO 训练阶段重新计算动作概率时，行为条件已经不一致。

因此当前 `CascadeReservoirRunner.insert()` 对行为 observation 和 mask 进行显式写入。

# 十五、长期 Constraint Cost

长期运行约束通过独立 cost 建模：

```text
ConstraintCostEvaluator
        ↓
constraint_1
constraint_2
...
constraint_K
        ↓
ConstraintBuffer
```

将实际存在的每一个“水库-约束类型”分别作为一项长期约束：

\[
\mathcal J=\{1,2,\ldots,K\}
\]

若某座水库不承担某类运行任务，则不建立对应长期约束。

对第 \(j\) 条长期约束，必须独立维护：

```text
constraint_id
raw_violation
normalization Z_j
tolerance epsilon_tol_j
active_flag chi_j,t
budget d_j
lambda_j
```

其中：

\[
\chi_{j,t}\in\{0,1\}
\]

表示第 \(j\) 条长期约束在时刻 \(t\) 是否实际生效。

很多生态下泄、保证出力和航运要求只在特定季节或运行阶段生效，因此不能把所有时间步都当成该约束的有效统计样本。

设第 \(j\) 条约束在时刻 \(t\) 的原始违反量为：

\[
v^{raw}_{j,t}
\]

先使用该约束自己的归一化参数：

\[
v_{j,t}
=
\frac{v^{raw}_{j,t}}{Z_j}
\]

再扣除该约束自己的容忍阈值：

\[
\tilde v_{j,t}
=
\max
\left(
0,
v_{j,t}-\epsilon^{tol}_j
\right)
\]

训练链路必须同时保留 violation 与 active flag。当前统一定义送入长期约束学习链路的等效 violation 为：

\[
c^{train}_{j,t}
=
\chi_{j,t}\tilde v_{j,t}
\]

因此：

```text
chi_j,t = 1
→ 当前时间步是第 j 条约束的有效样本

chi_j,t = 0
→ 当前时间步不能被当成第 j 条约束的有效违规样本
```

`ConstraintBuffer` 至少要能够恢复：

```text
c_train[j,t]
active_flag[j,t]
```

并建议同时保存 `raw_violation[j,t]`，用于论文统计和调试。

对于当前训练批次 \(\mathcal B\)，若第 \(j\) 条约束存在有效生效样本，则只在实际生效时段统计该约束的平均违反程度：

\[
\hat J_j
=
\frac{
\sum_{t\in\mathcal B}
\gamma^t
\chi_{j,t}
\tilde v_{j,t}
}{
\sum_{t\in\mathcal B}
\gamma^t
\chi_{j,t}
}
\]

然后与对应约束预算 \(d_j\) 比较，并更新独立的拉格朗日乘子：

\[
\lambda_j
\leftarrow
\left[
\lambda_j
+
\eta_\lambda
\left(
\hat J_j-d_j
\right)
\right]_+
\]

当：

\[
\sum_{t\in\mathcal B}\chi_{j,t}=0
\]

即该约束在整个 batch 内完全没有生效时：

```text
不统计该约束的 batch 平均违反程度
不更新该约束对应的 lambda_j
```

不能把“没有生效”误写成“有效的零违规样本”再参与 multiplier 更新，否则会人为降低该约束的约束压力。

当前真正启用哪些长期约束，以及每条约束的 \(Z_j\)、\(\epsilon^{tol}_j\)、\(d_j\) 等参数，以 YAML、数据文件和已有 Python 配置为准。

如果项目数据中没有可靠的阈值或预算，AI 不得自行创造。

# 十七、Lagrangian Advantage

Reward TD error：

\[
\delta_t^R
=
r_t
+
\gamma V^R(x_{t+1})
-
V^R(x_t)
\]

Reward advantage：

\[
A_t^R
=
\operatorname{GAE}(\delta_t^R)
\]

第 \(j\) 条长期约束使用第十五节定义的等效 violation：

\[
c^{train}_{j,t}
=
\chi_{j,t}\tilde v_{j,t}
\]

Constraint Critic TD error：

\[
\delta_t^{C_j}
=
c^{train}_{j,t}
+
\gamma V^{C_j}(x_{t+1})
-
V^{C_j}(x_t)
\]

第 \(j\) 条长期约束 advantage：

\[
A_t^{C_j}
=
\operatorname{GAE}(\delta_t^{C_j})
\]

Actor 使用：

\[
A_t^L
=
A_t^R
-
\sum_j
\lambda_j
A_t^{C_j}
\]

在一个训练批次的 Actor 更新前：

```text
先固定 lambda_snapshot
```

五个 Actor 在本轮都使用同一组 \(\lambda\)。

不得在五个 Actor 的同一轮 HAPPO 顺序更新中途修改 \(\lambda\)。

完成本轮 Actor 和 Critic 更新后，再根据第十五节定义的 active-period batch 统计更新各个 \(\lambda_j\)。

# 十八、动作采样顺序和 HAPPO 参数更新顺序

两个顺序必须明确区分。

真实水力动作顺序：

```text
WDD → BHT → XLD → XJB → THR
```

HAPPO 参数更新顺序：

```text
随机 agent order
```

例如：

```python
torch.randperm(num_agents)
```

因此：

```text
水力动作顺序固定
≠
Actor 参数更新顺序固定
```

但是，HAPPO 也不能退化为“随机顺序分别对五个 Agent 独立执行一次 PPO”。

训练时必须使用轨迹采样阶段真实保存的：

\[
(o^{dec}_{i,t},M_{i,t},a_{i,t},\log\pi^{old}_{i,t})
\]

在完全相同的行为条件下计算第 \(i\) 个 Agent 的新旧策略概率比：

\[
\rho_{i,t}
=
\frac{
\pi_{\theta_i}
\left(
a_{i,t}\mid o^{dec}_{i,t},M_{i,t}
\right)
}{
\pi_{\theta_i^{old}}
\left(
a_{i,t}\mid o^{dec}_{i,t},M_{i,t}
\right)
}
\]

每次策略优化随机生成更新顺序：

\[
\sigma
=
(\sigma_1,\sigma_2,\ldots,\sigma_N)
\]

初始化：

\[
\mu_{0,t}=1
\]

当准备更新顺序中的第 \(m\) 个 Agent \(\sigma_m\) 时，前 \(m-1\) 个 Agent 已经完成更新，因此需要累计这些已更新 Agent 的最终新旧策略概率比：

\[
\mu_{m-1,t}
=
\prod_{k=1}^{m-1}
\rho_{\sigma_k,t}
\]

当前 Agent 的 HAPPO surrogate 必须把该累计 probability ratio 带入：

\[
L_{\sigma_m}
=
\mathbb E_t
\left[
\min
\left(
\rho_{\sigma_m,t}
\mu_{m-1,t}
A_t^L,
\operatorname{clip}
(
\rho_{\sigma_m,t},
1-\epsilon,
1+\epsilon
)
\mu_{m-1,t}
A_t^L
\right)
\right]
\]

具体代码可以把上述量实现为 surrogate objective，或者实现为其相反数 loss；但算法语义必须保持一致。

当前 Agent 更新完成后：

1. 用更新后的策略，在原轨迹保存的同一个 \(o^{dec}\)、Mask 和 action 条件下重新计算该 Agent 的最终 new/old ratio；
2. 将该最终 ratio 累乘进当前 \(\mu\)；
3. 把新的累计 ratio 作为固定量传给更新顺序中的下一个 Agent；
4. 直到五个 Actor 全部完成一次 HAPPO 更新。

因此必须保持：

```text
真实动作采样：
WDD → BHT → XLD → XJB → THR

参数更新：
随机 sigma

HAPPO 顺序依赖：
已更新 Agent 的 ratio
→ 累乘到后续 Agent 的 surrogate
```

三者不能混为一件事。
