# S3 分级松弛与最终违反量比较：暂行实施方案

日期：2026-09-27。适用于当前五库串联系统 WDD → BHT → XLD → XJB → THR。

## 1. 本次决定及依据

用户已允许先设置一个具体的 P2 最大松弛值，并暂用按 P2、P3、P4 优先级比较最终候选动作违反程度的方案。

本方案补充《论文与代码统一上下文_严谨修订版.md》第 9 节尚未给定的参数和工程比较规则：

- **P2 水位上限：在当日正常运行上限基础上，最多增加 0.20 m。**五库暂用同一数值，所有运行阶段适用。
- **P2 水位下限：最大降低量为 0 m。**当前数据中 P2 下限等于 P1 物理最低水位，不向下突破。
- P1 水位、库容和下泄边界始终保持不变。P2 放宽后的边界仍与 P1 取交集。
- 最终兜底用三元组 `(V2, V3, V4)` 作字典序比较；全部相同，按完整五库动作索引元组的字典序选择。

**0.20 m 是用户授权采用的临时算法实验参数，尚无调度规程或工程论证依据。**它不是论文给定值，也不是五库实际运行的授权边界。后续取得依据后，应按库、按阶段重新审定配置并重新评估。

本次未修改 AGENTS.md、原始水位数据、动作数、P1、P3/P4 参数或 Layer 2。

## 2. 两种顺序的区别

| 用途 | 顺序 | 意义 |
|---|---|---|
| 约束重要性 | P1 > P2 > P3 > P4 | P1 绝对保持，其余按优先级处理 |
| 恢复联合可行集 | P4 → P3 → P2 | 从最低优先级开始松弛，恢复后立即停止 |
| 最终兜底动作比较 | 先 V2，再 V3，再 V4 | 只有各级最大松弛都失败后才采用 |

比较顺序不改变松弛顺序；最终比较也不采用把不同优先级直接相加的加权总分。

## 3. P2 最大松弛边界

设库 i 当日原始 P2 下限/上限分别为 L2_i、U2_i，P1 下限/上限分别为 L1_i、U1_i。
配置最大下调量 Dminus_i = 0 m、最大上调量 Dplus_i = 0.20 m。

使用一个五库共用的松弛比例 α ∈ [0, 1]：

```text
L2_i(α) = max(L1_i, L2_i − α × Dminus_i)
U2_i(α) = min(U1_i, U2_i + α × Dplus_i)
```

不存在的单侧 P2 边界保持不设置。当前环境提供完整上下限。

“最小”指**沿上述共同 α 参数化方向，使完整五库联合路径首次恢复的最小比例**，不是对五库独立松弛量求最小和，也不是先后单独放宽某一座水库。此参数化属于暂行工程选择。

按当前 `data/cascade_reservoir/constraints/water_level_limits.csv`：

| 库 | P1 下限（m） | 汛期原 P2 上限（m） | 汛期最大 P2 上限（m） | 其他阶段原 P2 上限（m） | 其他阶段最大 P2 上限（m） |
|---|---:|---:|---:|---:|---:|
| WDD | 945 | 952 | 952.20 | 975 | 975.20 |
| BHT | 765 | 785 | 785.20 | 825 | 825.20 |
| XLD | 540 | 560 | 560.20 | 600 | 600.20 |
| XJB | 370 | 370 | 370.20 | 380 | 380.20 |
| THR | 145 | 145 | 145.20 | 175 | 175.20 |

表中是允许尝试的最大边界；具体某天可能完全不需要松弛，也可能只需要其中很小一部分。

**边界含义：0.20 m 限制的是 P2 有界恢复阶段。**若全部运行约束最大松弛仍无完整路径，修订版规定的最终兜底仅把 P1 作为硬约束，所选动作可能超出 P2 的 0.20 m 边界或 P3/P4 最大松弛边界。这时必须标为 `min_violation_fallback` 并如实记录，不能称为正常/有界可行。如果未来需要把 0.20 m 设为连最终兜底也不可突破的硬边界，则需另外修改并确认最终兜底的定义。

## 4. 每个决策日的具体执行步骤

### 步骤 A：建立正常上下文

读取当前库容、水位、当日来水、运行阶段、上一日真实下泄，建立正常 P1/P2/P3/P4。

- 只有 WDD 使用外部总来水；其余库使用区间来水。
- 候选下游入流 = 直接上游候选总下泄 + 当日区间来水。
- P4 仅在 `dry_supply` 生效，其他阶段不参与松弛和评分。
- 首日没有上一日下泄，关闭 P3 下泄变化项，仍保留 P3 水位变化项。

### 步骤 B：正常 S2

执行完整 S201 → S202 → S203。如果 WDD 的 root joint-safe mask 非空，返回 `normal`，进入 S4。

### 步骤 C：最小必要松弛 P4

仅在 P4 生效时处理。P1/P2/P3 保持正常值。

当前已有配置：下泄/入流比例从 1.0 最多降至 0.75。
先检查 0.75 是否能恢复完整路径；可以时二分搜索最大的可行比例，返回 `p4_relaxed`。
如最大松弛仍失败，固定为 0.75，进入下一步。未生效的 P4 保持关闭。

### 步骤 D：最小必要松弛 P3

P1/P2 保持正常，P4 保持最大松弛结果。

当前已有配置：水位变化限额与下泄变化限额同乘因子，因子从 1 最多增至 2。
先检查因子 2；可行时二分搜索最小可行因子，返回 `p3_relaxed`。
若仍失败，固定 P3 因子为 2，进入 P2 阶段。

正常 P3 水位变化限额：WDD 0.30、BHT 0.50、XLD 0.90、XJB 0.20、THR 1.40 m。
正常 P3 下泄变化限额：`max(0.5 × 前日实际下泄, 5000 m³/s)`。
这些均为已有配置，本次不调整。

### 步骤 E：最小必要松弛 P2

保持 P1 不变，P3/P4 固定在各自最大允许松弛处。

1. 用 α = 1 构造新的 P2 边界，重新执行完整 S201 → S202 → S203。
2. 如果依然没有完整路径，进入步骤 F。
3. 如果有完整路径，以 α = 0 为不可行端、α = 1 为可行端进行二分搜索。
4. 每个中点都重新建立全部局部可行集、相邻兼容矩阵、后向可延拓结果。
5. 中点可行则移动可行端；不可行则移动不可行端。
6. 返回最终可行端及其 S203 结构，模式为 `p2_relaxed`；不强制指定单一动作，仍由五个 Actor 顺序条件采样。

当前 `safety.relaxation.tolerance = 0.001`、`max_iterations = 16`。
P4 容差作用于比例；P3/P2 容差作用于归一化松弛比例。P2 α 区间收缩到 0.001 内，对应最多 0.0002 m 的参数搜索区间（未触及 P1 截断时）。返回可行端，不声称有限精度二分得到数学上的精确最小值。若先到迭代上限，精度以剩余区间为准。

所有搜索仅构造候选上下文，不推进日期、库容、水位或动作历史。

### 步骤 F：最终最小运行违反兜底

1. 仅使用 P1，重新执行完整 S201 → S202 → S203。
2. 如果连 P1-safe 完整路径也不存在，抛出明确硬不可行错误；不扩大 P1，不伪造 mask。
3. 对所有 P1-safe 完整路径，按下一节的规则计算 `(V2, V3, V4)`。
4. 用动态规划找字典序最小的完整路径；不分别选择五个单库的局部最优动作。
5. 返回 `min_violation_fallback`，保存强制五库联合动作及三项总违反量。
6. S4 按 WDD→THR 顺序使用该路径的一位有效 mask，仍保存真实 observation、mask、action、log probability。

最终兜底时 one-hot mask 是合法的强制路径表达，不是把空 mask 改为全 1。

## 5. 最终比较公式

### 5.1 统一参考边界

**全部违反量相对于原始、未松弛的正常 P2/P3/P4 边界计算。**不会因为已经放宽边界，就把正常要求的违反量清零。

使用每条候选路径自己的入流、候选下泄和水量平衡推算下一日水位：

```text
Vnext_i = V_i + (I_i − Q_i) × Δt
Hnext_i = Z(Vnext_i)
I_1 = 外部来水
I_i = Q_(i−1) + 区间来水_i
```

### 5.2 P2：水位越界

```text
raw2_lower_i = max(0, L2_i − Hnext_i)       [m]
raw2_upper_i = max(0, Hnext_i − U2_i)       [m]
Z2_i = U1_i − L1_i                         [m]
v2_i = (raw2_lower_i + raw2_upper_i) / Z2_i
V2 = Σ_i v2_i
```

归一化使用 P1 水位跨度，要求严格大于零。避免使用 P2 自身区间宽度，因为当前向家坝、三峡汛期 P2 上下界重合，会出现分母为零。

此处用 P1 跨度仅作为无量纲化尺度，**不表示 P2 可以直接放宽到 P1 上限**。

### 5.3 P3：日水位变化与日下泄变化

设正常水位变化限额为 dH_i：

```text
raw3_level_i = max(0, |Hnext_i − Hcurrent_i| − dH_i)       [m]
v3_level_i = raw3_level_i / dH_i
```

若有前日真实下泄 Qprev_i：

```text
dQ_i = max(release_change_ratio × Qprev_i, release_change_floor_m3s)
raw3_release_i = max(0, |Q_i − Qprev_i| − dQ_i)            [m³/s]
v3_release_i = raw3_release_i / dQ_i
```

首日没有前日真实下泄时，`raw3_release_i = v3_release_i = 0`，不伪造历史。
正常 dH_i 和 dQ_i 必须为正；当前配置满足，加载时也校验正的下泄变化 floor。

```text
v3_i = v3_level_i + v3_release_i
V3 = Σ_i v3_i
```

### 5.4 P4：最低下泄/入流比例

P4 生效且正常要求 Qrequired_i = normal_ratio × I_i > 0 时：

```text
raw4_i = max(0, Qrequired_i − Q_i)          [m³/s]
v4_i = raw4_i / Qrequired_i
```

P4 未生效或正常要求为零时，该项记零；不除以零。

```text
V4 = Σ_i v4_i
```

### 5.5 数值容差与聚合

- 沿用当前求解器数值容差：水位原始超限量不超过 `1e-8 m` 记零；流量原始超限量不超过 `1e-7 m³/s` 记零。超过容差时记录完整超限量，而非减去容差。
- 同级按库求和，P3 内部两个无量纲子项相加；没有额外权重。
- 三元组之间不相加、不用大权重近似优先级。
- 三元组按计算所得浮点值逐项比较；不额外引入“近似相等”的阈值。
- 所有分量完全相同时，比较完整动作索引元组 `(a_WDD, a_BHT, a_XLD, a_XJB, a_THR)`，取字典序较小者，保证可重复。

例：A = `(0.010, 3.0, 1.0)`，B = `(0.011, 0.0, 0.0)`，选 A；P2 的较小违反不能被 P3/P4 改善抵消。
若 A = `(0.010, 0.2, 0.8)`、B = `(0.010, 0.3, 0.0)`，仍选 A。

## 6. 动态规划为什么比较的是完整联合动作

当前没有河道时滞，某库候选入流只依赖直接上游动作。因此可以在相邻兼容图上求解：

1. WDD 每个 P1-safe 动作保存自身三元组及单元素路径。
2. 到 BHT 时，枚举合法的 WDD→BHT 边，累加 BHT 在对应候选入流下的三元组。
3. 对每个 BHT 末端动作，只保留总分字典序最小的前缀；同分保留完整前缀索引较小者。
4. 同样推进 XLD、XJB、THR。
5. 在 THR 各个可达末端中选出最优完整路径。

复杂度随相邻动作对增长，无需枚举 201⁵ 条路径。测试另用小型图穷举全部路径验证动态规划结果。

## 10. 后续修复：P4 纳入 ConstraintContext / S201

本次处理修订版第 6.3 节的接口职责一致性。此前 P4 已通过 S3 的附加 mask 参与联合可行性，但直接调用 S201 时无法从 ConstraintContext 获得 P4，返回的有效约束边界也遗漏 P4。

修改后的调用流程：

```text
S3 根据阶段及当前松弛比例构造 ConstraintContext(p1, p2, p3, p4)
→ S202 为每个上游候选动作计算下游候选入流
→ S201 接收该次 inflow_m3s
→ context.resolve(inflow_m3s=该次候选入流)
→ P4 最低下泄 = release_inflow_ratio × inflow_m3s
→ 与 P1/P3 泄量边界、P1/P2/P3 水位边界统一取交集
→ 反推动态泄量区间，生成局部 mask
→ S202/S203 形成完整路径
```

- 新增冻结的 `P4Constraints`，显式保存当前有效下泄/入流比例；`context.p4 = None` 表示未生效或最终 P1-only 搜索。
- P4 生效但解析上下文未提供入流时明确报错，不能使用零或昨天入流代替。
- 正常 P4 比例及最大松弛比例仍分别为 1.0 和 0.75，均来自原 YAML；未新增运行参数。
- S3 删除外部追加 P4 mask 的逻辑，只负责构造上下文及分级搜索，S201 自身不松弛。
- `EffectiveS201Bounds.release` 和最终局部 mask 均反映 P4。有效边界交集为空时按 S201 既有空区间规则返回全 false；严格空区间不会靠数值容差变成可行。
