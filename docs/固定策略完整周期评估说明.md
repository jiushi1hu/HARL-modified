# 固定策略完整周期评估

## 使用方法

在仓库根目录、harl Python 环境执行：

```bash
PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python python -m examples.evaluate_cascade \
  --model-dir "新实验目录/models" \
  --output-dir "results/frozen_comparison_01"
```

将 `新实验目录/models` 替换为保存修复后产生的实际模型目录。
默认以该目录下的 `initial/` 为起始策略，也可通过 `--baseline-dir` 显式指定。
输出目录必须尚不存在，避免覆盖已有评估结果。
不要指向当前未产生检查点的旧实验目录；程序会明确报缺失文件。

## 评估语义

- 只支持起始 run_start 与训练后 periodic/final 检查点对照。
- 两组环境配置、模型配置和算法配置必须一致，否则拒绝比较。
- 使用各检查点保存的配置，不读取当前 YAML 来覆盖原实验物理参数。
- 两组检查点先复制到输出目录，记录来源及文件 SHA256；复制期间源文件变化则拒绝继续。
- 使用现有 `CascadeReservoirRunner.eval()`、同一 S201/S202/S203/S3 和 SequentialSampler，按水流方向确定性 argmax 选择动作。
- 从环境 reset 初始状态运行到配置结束日期，要求恰好覆盖全部日期且最后一天 done。当前正式配置为 1096 天，不受训练 rollout 长度限制。
- 不调用 run、compute、train；评估前后核对五个 Actor、全部 Critics、ValueNorm 和 lambda 的摘要一致。
- 不更改原检查点，不自动开启训练或停止其他进程。

这里比较的是确定性动作选择；不与随机采样的训练回报直接混比。run_start 如果来自加载旧模型，代表本次训练起点，不代表随机初始化。

## 输出

- `comparison.md`：发电量、累计奖励、每项约束 cost 和违反天数、末期库容对照。
- `comparison.json`：完整指标、日期、检查点元数据、参数摘要和详细日志位置。
- `baseline.json` / `trained.json`：各自的结果。
- `checkpoints/`：本次评估使用的固定检查点副本及文件摘要。
- `baseline/` / `trained/`：现有 Logger 生成的逐日系统、逐库及逐项约束 CSV。

报告同时列出全周期折扣平均和等权有效样本平均。年度统计另行计算；其中年度折扣从该年第一天重新计权，仅用于诊断，不替代训练批次公式。整段没有激活样本时均值为 null，不伪造零违规。
另记录安全恢复模式天数、逐库 P2 原始上下边界最大违反量、末期水位与库容。未添加新的物理边界或终端库容要求。

发电量增加不自动代表约束改善；cost 不是缺水百分比。相同训练历史区间的对照不代表持出情景泛化，也不是多随机种子的显著性结论。

## 验证与当前限制

```bash
PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python python -m unittest examples.test_cascade_evaluation -v -f
```

3 项测试覆盖：折扣/有效样本统计、未激活均值、缺失检查点拒绝、环境配置不一致拒绝，以及真实短周期训练后的两个检查点加载和完整评估。
真实测试使用独立临时数据副本的 3 天周期、2 步训练 rollout，确认评估仍走完 3 天；同时禁止调用 run/compute/train，验证评估前后参数一致。没有改动正式数据文件。

短周期测试通过不等于完成了正式 1096 天性能实验。检查时旧 `test_full_episode_36` 的 models 仍为空，无法用它完成正式训练前后对照。需要先获得新版保存逻辑产生的起始及训练后模型。
