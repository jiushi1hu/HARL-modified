## 0. 文档使用原则
1. **专利语义优先。** S1、S2/S201-S203、S3、S4/S401-S403、S5 的因果关系、变量语义和更新逻辑不得因工程便利而改变。
2. **仓库参数不等于专利限定。** 五座具体水库、201 个动作、17/18/85 维观测、2023-2025 仿真区间、P3/P4 数值参数、HARL wrapper 形状等均属于当前仓库实例化。
3. **代码必须显式区分候选量与实际量。** 特别是 `Q_target`/`Q_exec`、candidate inflow/actual inflow、base observation/decision observation、local mask/joint-safe mask。
4. **第一层不能用奖励惩罚替代。** 当前决策步的联合可行性通过局部可行性、相邻兼容性、下游可延拓性和必要时的分级最小松弛保证。
5. **第二层不能替代第一层。** 生态下泄、保证出力、航运等长期运行约束通过 Constraint Critic + Lagrangian 学习；它们与当前步 P1-P4 可行性处理的角色不同。
6. **不允许“为了跑通”篡改算法。** mask 为空不能改全 1；P1 不能扩大；动态 observation/mask 不能在训练时重新构造来代替行为轨迹中真实保存的条件。

## 1. 研究对象、当前仓库实例与总体目标
【专利规定】对于由 \(N\) 座串联水库构成的系统，每座水库对应一个相互协作的智能体，按照水流方向编号 \(1,\ldots,N\)。各智能体共享系统发电奖励，但可承担不同的长期运行约束。  
【仓库实现】当前实例固定为五库：
```text
WDD（乌东德）
  ↓
BHT（白鹤滩）
  ↓
XLD（溪洛渡）
  ↓
XJB（向家坝）
  ↓
THR（三峡）
```
对应：

agent_0 = WDD
agent_1 = BHT
agent_2 = XLD
agent_3 = XJB
agent_4 = THR

五个 Actor 独立，不共享策略参数： 
```yaml 
share_param: false
```
总体目标不是最大化单日发电量，而是在当前决策步满足可执行安全要求的前提下，学习兼顾梯级发电收益与各库实际承担的长期运行约束的联合调度策略。

### 1.1 “双层安全”的严格含义
第一层是当前决策步可行性保障层：面向当前调度时段，对梯级联合动作进行可行性筛选、恢复与顺序执行。保证各水库当前动作在上下游水力耦合条件下能够形成完整可执行的梯级联合动作。S1 建模、S2 联合可行性动作构造、S3 空集恢复、S4 顺流条件采样。  
第二层是策略训练与长期约束优化层：面向长期策略学习，基于HAPPO-Lagrangian对发电收益和多类长期运行约束进行联合优化。在提高梯级发电收益的同时，通过拉格朗日乘子实现对生态下泄、保证出力、航运等长期约束的持续协调与控制。S5 HAPPO-Lagrangian，通过 Reward Critic、Constraint Critics 和独立拉格朗日乘子进行策略优化。

方法流程：

## 2. 时间尺度、水力拓扑与来水语义
采用日尺度，并在该尺度下不单独考虑相邻水库河道传播时滞。此时，下游第 \(i\) 座水库当期实际入流为：
\[
I_{i,t}=Q^{exec}_{i-1,t}+I^{int}_{i,t},\qquad i=2,\ldots,N
\]
其中 \(Q^{exec}_{i-1,t}\) 是直接上游当前实际总下泄，\(I^{int}_{i,t}\) 是两库间区间入流。最上游入流由梯级外部来水确定。  

Δt = 86400 s
仿真区间 = 2023-01-01 ~ 2025-12-31
当前不显式考虑河道传播时滞

数据字段语义：
WDD_external_inflow_m3s 是最上游水库乌东德的外部来水
BHT_interval_inflow_m3s 是乌东德-白鹤滩的区间入流
XLD_interval_inflow_m3s 是白鹤滩-溪洛渡的区间入流
XJB_interval_inflow_m3s 是溪洛渡-向家坝的区间入流
THR_interval_inflow_m3s 是向家坝-三峡的区间入流

因此下游 CSV/数据源中的 `*_interval_inflow_m3s` 必须保持为**区间入流**，不能预先累加成总入流。实际总入流只允许在上游当前动作已确定后由顺序采样链生成。

### 2.1 候选入流与实际入流必须分离
S2 中的候选入流：
\[
I^{cand}_{i,t}(a_{i-1})
=Q^{tar}_{i-1,t}(a_{i-1})+I^{int}_{i,t}
\]
只用于候选动作兼容性判断，**不能写回环境当前状态，也不是实际发生的入流**。  
S4 中的实际入流：
\[
I^{exec}_{i,t}
=Q^{exec}_{i-1,t}+I^{int}_{i,t}
\]
只在直接上游动作已实际确定后产生，并进入下游真实 decision observation。

### 2.2 `Q_target` 与 `Q_exec`
S2 使用动作映射得到的目标总下泄 \(Q^{tar}\) 构造候选入流；S4 使用真实执行后的总下泄 \(Q^{exec}\) 构造下游实际入流。两者在符号和语义上必须区分，后者只有Actor真正选完动作以后才出现。
在当前实现中，Actor选择的是经过可行性筛选后的离散动作，该动作通过预设映射唯一对应一个目标总下泄量 Q^tar_i,t。
由于程序在动作选定后没有额外设置动作投影、二次裁剪或执行层修正，因此该目标总下泄量直接作为环境实际执行的总下泄量，即 Q^exec_i,t = Q^tar_i,t。
二者仍在符号上进行区分，是为了对应“候选/目标下泄量”和“动作确定后的实际下泄量”两个不同阶段，同时为后续可能加入强制泄洪、设备故障修正等执行层处理预留接口。
当前程序约定：
\[
Q^{exec}_{i,t}=Q^{tar}_{i,t}
\]

## 4. S1：构建约束合作型马尔可夫博弈模型
合作型马尔可夫博弈包含系统状态空间、各智能体观测空间、各智能体动作空间、状态转移关系、共享发电奖励和折扣因子，并在此基础上加入各库实际承担的长期运行约束。

### 4.1 系统状态
第 \(i\) 座水库动态信息为 \(x^{dyn}_{i,t}\)，固定物理参数为 \(\kappa_i\)：
\[
s_t=\{x^{dyn}_{i,t},\kappa_i\}_{i\in\mathcal R}
\]
动态信息至少包括：当前水位、库容、当前可获得的区间入流、上一时刻实际下泄、上一时刻出力、当前运行阶段相关信息。固定参数可包括：库容-水位关系、装机容量、总泄流能力及其他调度计算参数。

### 4.2 base observation
\[
o^{base}_{i,t}
=\left(o^{loc}_{i,t},o^{up}_{i,t},o^{down}_{i,t},o^{sys}_t\right)
\]
其中：
- \(o^{loc}\)：本库当前水位、库容、区间入流、季节相位、下一时刻水位边界、上一时刻动作、上一时刻实际下泄、发电状态等；
- \(o^{up}\)：直接上游当前可获得水位、历史下泄等；
- \(o^{down}\)：直接下游运行状态、剩余可调节库容空间等；
- \(o^{sys}\)：梯级总库容状态、系统发电状态、汛期等系统信息。
对于最上游水库不存在的上游观测、最下游水库不存在的下游观测，可在程序中采用零填充、占位或其他统一编码方式

### 4.3 Decision observation
最上游当前入流在动作选择前已经确定，因此：
\[
o^{dec}_{1,t}=o^{base}_{1,t}
\]
下游 \(i=2,\ldots,N\) 必须等直接上游动作确定后，先计算：
\[
I_{i,t}=Q^{exec}_{i-1,t}+I^{int}_{i,t}
\]
再形成：
\[
o^{dec}_{i,t}=(o^{base}_{i,t},I_{i,t})
\]
因此：
base observation：联合动作采样前即可获得
decision observation：Actor真正采样时使用

对下游而言，两者绝不能互换。

### 4.4 当前仓库 observation 维度
当前文档约定每库 `base observation = 17` 维；下游实际 Actor 额外拼接 1 维当前总入流：

WDD  : 17
BHT  : 18
XLD  : 18
XJB  : 18
THR  : 18

当前下游附加入流编码约定：

encoded_current_inflow =
current_inflow_m3s / 本库 action mapper.map_max_release_m3s

该归一化只作用于神经网络特征，不能改变真实 m³/s 入流、候选下泄、mask 或环境物理执行。`SequentialSamplingResult.inflows_m3s` 应保存原始 m³/s。  
上述 17/18 维及归一化方式是仓库特定设计，必须以真实代码为准；若修改 observation schema，旧模型检查点不可默认兼容。

### 4.5 HARL wrapper observation

由于 HARL/vector env 要求各 agent 的观测维度一致，而最上游水库与下游水库的实层际决策观测维度可能不同，因此接口可通过补 0 等方式统一 observation shape。该补充值仅用于满足 wrapper 的数据格式要求，不代表新增物理信息。训练时用于重新计算动作概率的 observation，应与智能体实际采样动作时使用的 \(o^{dec}_{i,t}\) 保持一致。

### 4.6 离散动作与目标总下泄映射
第 \(i\) 座水库采用离散动作空间。若候选动作索引：
\[
k\in\{0,1,\ldots,N_a-1\}
\]
则归一化索引：
\[
u(k)=\frac{k}{N_a-1}
\]
动作映射：
\[
Q^{tar}_{i,t}(a_i)
=Q^{map,min}_i+
\left(Q^{map,max}_i-Q^{map,min}_i\right)\psi_i(u(k))
\]
要求：
\[
\psi_i(0)=0,\qquad \psi_i(1)=1
\]
且 \(\psi_i\) 严格单调递增。  
\(Q^{map,min/max}\) 定义的是**动作编码范围**，不是当前时刻动态安全范围；后者由 S201 计算。  

当前 `ReleaseActionMapper` 使用线性映射，线性仅是专利允许的 \(\psi_i\) 的一个特例；动作数由配置决定：
```yaml
action:
  num_actions: 201
```
代码不得另行写死动作数。

### 4.7 水量平衡与水位更新
对第 \(i\) 座水库：
\[
V_{i,t+1}
=V_{i,t}+\left(I_{i,t}-Q^{exec}_{i,t}\right)\Delta t
\]
若库容-水位关系：
\[
V_i=f_i(h)
\]
则：
\[
h_{i,t+1}=f_i^{-1}(V_{i,t+1})
\]
`reservoir_physics.py` 中所有 transition 必须与这一守恒关系一致；单位换算必须在同一处显式完成。

### 4.8 总下泄、过机流量、非发电下泄、出力与发电量
\[
Q^{exec}_{i,t}=Q^{gen}_{i,t}+Q^{non}_{i,t}
\]
在不存在强制非发电泄放、机组运行限制或其他特殊要求时，总下泄优先分配为过机流量；超过当前有效过机能力的部分作为非发电下泄。出力：
\[
P_{i,t}
=\min\left\{P_i^{inst},
\eta_i\rho_w g H_{i,t}Q^{gen}_{i,t}\right\}
\]
发电量：
\[
E_{i,t}=P_{i,t}\Delta t
\]
系统共享发电奖励：
\[
r_t=\frac{\sum_{i\in\mathcal R}E_{i,t}}{E^{ref}}
\]

\(E^{ref}\) 是固定数值归一化尺度，但专利没有规定其具体计算公式。  
当前文档约定：
\[
E^{ref}=\left(\sum_i P_i^{inst}\right)\Delta t
\]
即“五库全部按装机容量运行一个日步长”的理论能量尺度。若代码实际实现不同，应以真实配置/代码为准，同时保持“固定归一化尺度”的专利语义。

## 5. 第一层：当前决策步联合可行性保障
第一层目标不是“每库各自有动作”而是：
> 在 Actor 采样前构造至少一条从最上游到最下游的完整可执行候选动作路径，并在真实顺序采样过程中始终只沿仍可延拓的路径选择。

### 5.1 P1-P4 约束层级

\[
P1>P2>P3>P4
\]
优先级越高，越应保持。空联合可行集恢复时保持 P1 不变，按：
\[
P4\rightarrow P3\rightarrow P2
\]
依次处理。

#### P1：绝对物理安全约束
不可主动放宽，包括：
- 水量平衡；
- 实际总下泄物理能力上下限；
- 库容/水位绝对物理安全边界；
- 不可突破的设备能力边界；
- 达到预设紧急安全触发条件时必须执行的强制泄洪要求。
【实现约束】若仓库尚无“紧急强制泄洪触发条件”的可靠参数，不得自行编造；但一旦该规则被配置并触发，其语义属于 P1。

#### P2：运行阶段时变水位控制约束
包括防洪期、蓄水期、消落期等不同运行阶段的时变水位控制边界。P2 是允许运行层面松弛的最高优先级约束，但只有 P4、P3 已到各自最大允许松弛仍无法恢复联合可行性时才允许处理 P2。

#### P3：相邻时段变化约束
包括相邻时段水位变化率、下泄变化率、最大水位变化速度等。  
当前文档约定：
```yaml
safety:
  p3:
    release_change_ratio: 0.5
    release_change_floor_m3s: 5000.0
    max_relaxation_factor: 2.0
    level_change_limit_m:
      WDD: 0.30
      BHT: 0.50
      XLD: 0.90
      XJB: 0.20
      THR: 1.40
```
正常下泄变化约束：
\[
|Q_t-Q_{t-1}|
\le \max(0.5Q_{t-1},5000)
\]
仓库在 P3 松弛时对允许变化范围乘 relaxation factor。  
首日若无可信上一日实际下泄：
```text
previous_release_m3s = None
```
不得伪造历史值；只取消依赖上一时刻下泄的那一项 P3 子约束。若当前水位真实已知，则由当前水位与下一时刻水位构成的变化约束仍可有效。具体也就是说：
首日因为缺少上一日历史下泄量，无法计算对应的下泄变化率约束，因此该子约束暂不生效；从第二天开始已有前一日实际下泄量，就可以正常启用。

#### P4：枯水期泄流与入流关系约束
P4 属于枯水期泄流与入流关系类约束。  
当前形式：
\[
Q^{tar}_{i,t}\ge\eta_4 I_{i,t}
\]
当前配置：
```yaml
safety:
  p4:
    normal_release_inflow_ratio: 1.0
    min_release_inflow_ratio: 0.75
```
P4 在其适用运行阶段正常生效时，必须从一开始就参加 S201/S202/S203；它不是“只有 mask 空以后才出现”的约束。S3 只负责在联合可行集为空时逐步降低/放宽该运行要求。

## 6. S201：给定入流条件下的单库局部可行性
### 6.1 S201 的函数语义
S201 应被实现成可复用的“给定入流 + 给定约束上下文 → 本库候选动作局部 mask”函数：

LocalFeasibility(
    reservoir_state,
    given_inflow,
    action_candidates,
    constraint_context
) -> local_mask

对于下游库，S202 会用不同上游候选动作生成不同 `given_inflow`，因此不能假定每个下游库在整个 S2 过程中只有一个固定 local mask。
也就是说：S201 用于判断某座水库在给定入流条件下各候选动作是否局部可行，并生成对应的局部动作 mask。对于下游水库，由于不同上游候选动作会形成不同的候选入流，因此在 S202 中需要针对每一种候选入流重新执行 S201。也就是说，下游水库的 local mask 会随上游候选动作变化，并不是在整个 S2 过程中固定不变的。

### 6.2 由下一时刻水位边界推导动态下泄区间
设下一时刻允许水位：
\[
h^{min}_{i,t+1}\le h_{i,t+1}\le h^{max}_{i,t+1}
\]
通过 \(V_i=f_i(h)\) 得：
\[
V^{low}_{i,t+1}=f_i(h^{min}_{i,t+1}),\qquad
V^{high}_{i,t+1}=f_i(h^{max}_{i,t+1})
\]
对任一候选总下泄 \(Q_{i,t}\)：
\[
V_{i,t+1}=V_{i,t}+(I_{i,t}-Q_{i,t})\Delta t
\]
为了不超过库容上限：
\[
Q_{i,t}\ge I_{i,t}
+\frac{V_{i,t}-V^{high}_{i,t+1}}{\Delta t}
\]
为了不低于库容下限：
\[
Q_{i,t}\le I_{i,t}
+\frac{V_{i,t}-V^{low}_{i,t+1}}{\Delta t}
\]
若当前物理总下泄能力为 \([Q^{min}_{i,t},Q^{max}_{i,t}]\)，则：
\[
Q^{safe,min}_{i,t}
=\max\left\{
Q^{min}_{i,t},
I_{i,t}+\frac{V_{i,t}-V^{high}_{i,t+1}}{\Delta t}
\right\}
\]
\[
Q^{safe,max}_{i,t}
=\min\left\{
Q^{max}_{i,t},
I_{i,t}+\frac{V_{i,t}-V^{low}_{i,t+1}}{\Delta t}
\right\}
\]
对动作 \(a_i\)：
\[
M^{local}_{i,t}(a_i)
=\mathbf 1\left[
Q^{safe,min}_{i,t}
\le Q^{tar}_{i,t}(a_i)
\le Q^{safe,max}_{i,t}
\right]
\]
局部可行动作集合：
\[
A^{local}_{i,t}
=\{a_i\in A_i:M^{local}_{i,t}(a_i)=1\}
\]

### 6.3 S201 还必须检查当前 `ConstraintContext` 中生效的可行性约束
专利把当前决策步参与联合可行性判断的约束分为 P1 与可松弛运行约束 P2/P3/P4。因此程序实现中，S201 对候选动作进行局部可行性判断时，应同时检查当前决策步实际生效的所有第一层可行性约束。

固定原则：
S201 只判断，不负责松弛。
S3 改变 constraint_context 后，重新运行 S201/S202/S203。

`S201` 不得自行偷偷放宽 P2/P3/P4，也不得修改 P1。
S201 本身只负责判断，不负责调整或放宽约束。当联合可行集为空时，由 S3 按优先级调整允许松弛的运行约束，再重新执行 S201/S202/S203。P1 绝对物理安全约束始终保持不变。

### 6.4 局部可行不等于梯级联合可行
即使：
```text
M_local[i][a_i] == 1
```
也只能说明第 \(i\) 座水库在当前给定入流下自身可行，不能说明该动作能与下游形成完整路径。因此 Actor 不能直接使用 `M_local` 作为最终动作 mask。

## 7. S202：相邻水库候选动作兼容关系
### 7.1 候选入流
对于下游 \(i=2,\ldots,N\)，上游候选动作 \(a_{i-1}\) 尚未真正执行。根据其目标总下泄构造：
\[
I^{cand}_{i,t}(a_{i-1})
=Q^{tar}_{i-1,t}(a_{i-1})+I^{int}_{i,t}
\]
该量只存在于当前决策步的候选兼容性计算中。

### 7.2 兼容矩阵
将 \(I^{cand}_{i,t}(a_{i-1})\) 作为 S201 的 `given_inflow`，判断下游候选动作 \(a_i\) 是否局部可行：
\[
C_{i,t}(a_{i-1},a_i)
=
\begin{cases}
1,& a_i\text{ 在 }I^{cand}_{i,t}(a_{i-1})\text{ 下局部可行}\\
0,& \text{否则}
\end{cases}
\]
若相邻两库均有 \(N_a\) 个动作，则 \(C_{i,t}\) 是 \(N_a\times N_a\) 二值矩阵。更一般地，若动作数不同，矩阵形状应为：
\[
|A_{i-1}|\times |A_i|
\]
五库需构造：
```text
C_BHT : WDD action  × BHT action
C_XLD : BHT action  × XLD action
C_XJB : XLD action  × XJB action
C_THR : XJB action  × THR action
```

### 7.3 S202 实现不变量
- 使用 `Q_target`，不是尚不存在的下游实际入流；
- 候选入流计算不能推进环境；
- 所有矩阵必须由同一个 `ConstraintContext` 生成；
- S3 每改变一个松弛等级/幅度，都必须重新得到与该上下文一致的兼容关系；
- 如果未来 `Q_exec != Q_target`，必须重新定义 S202 与真实执行之间的一致性机制。

## 8. S203：由最下游向最上游递推下游可延拓性
### 8.1 递推定义
定义：
\[
b_{i,t}(a_i)\in\{0,1\}
\]
表示候选动作 \(a_i\) 是否存在一条能够继续延拓到最下游的完整兼容路径。对最下游：
\[
b_{N,t}(a_N)=1
\]
这里的 1 只表示“不再需要检查更下游”；最下游动作针对给定上游候选动作是否局部可行，已经编码在 \(C_{N,t}\) 中。  
对：
\[
i=N-1,N-2,\ldots,1
\]
递推：
\[
b_{i,t}(a_i)
=
\mathbf 1\left[
\exists a_{i+1}\in A_{i+1}:
C_{i+1,t}(a_i,a_{i+1})=1
\land b_{i+1,t}(a_{i+1})=1
\right]
\]

### 8.2 最上游 root safe set
最上游还必须自身局部可行：
\[
A^{safe}_{1,t}
=
\left\{
a_1\in A_1:
M^{local}_{1,t}(a_1)=1
\land b_{1,t}(a_1)=1
\right\}
\]
root mask：
\[
M^{safe}_{1,t}(a_1)
=\mathbf 1[a_1\in A^{safe}_{1,t}]
\]

### 8.3 下游条件安全集合
给定直接上游动作 \(a_{i-1}\)，中间水库 \(i=2,\ldots,N-1\)：
\[
A^{safe}_{i,t}(a_{i-1})
=
\left\{
a_i\in A_i:
C_{i,t}(a_{i-1},a_i)=1
\land b_{i,t}(a_i)=1
\right\}
\]
最下游：
\[
A^{safe}_{N,t}(a_{N-1})
=
\left\{
a_N\in A_N:
C_{N,t}(a_{N-1},a_N)=1
\right\}
\]
条件 mask：
\[
M^{safe}_{i,t}(a_i\mid a_{i-1})
=
\mathbf 1[a_i\in A^{safe}_{i,t}(a_{i-1})]
\]

### 8.4 图论解释
S2 可理解为一个分层有向图：
```text
第 1 层：WDD 候选动作节点
第 2 层：BHT 候选动作节点
...
第 5 层：THR 候选动作节点
边：C_i(a_{i-1}, a_i) = 1
```
S203 做的是“从终点层反向标记所有可到达终点的节点”。它避免暴力枚举所有 \(N_a^N\) 联合动作；当前五库且每库 201 个动作时，更应避免构造完整笛卡尔积。

## 9. S3：联合可行集为空时的分级最小松弛
### 9.1 触发条件
若：
\[
A^{safe}_{1,t}=\varnothing
\]
说明当前约束上下文下不存在一组可从最上游逐级延拓到最下游的完整联合动作，启动 S3。

### 9.2 专利规定的严格恢复顺序
保持 P1 不变，按：
```text
阶段 0：原始 P1 + P2 + P3 + P4
  ↓ 若联合可行集为空
阶段 1：仅逐步放宽 P4；P1/P2/P3 保持
  ↓ P4 达到最大允许松弛仍为空
阶段 2：固定 P4 在其允许范围内的已处理结果，再逐步放宽 P3；P1/P2 保持
  ↓ P3 也达到最大允许松弛仍为空
阶段 3：在 P1 保持不变的前提下逐步放宽 P2
  ↓ P2/P3/P4 均到各自最大允许松弛仍为空
阶段 4：在所有满足 P1 的候选联合动作中，选择“运行约束违反程度最小”的联合动作
```
每一级都必须遵守：
```text
只放宽到“恢复至少一组完整梯级联合可行动作”所需的最小程度；
一旦恢复，立即停止，不继续放宽当前等级，也不触碰更高优先级等级；
不得超过该等级预设最大允许松弛范围。
```

### 9.3 对原文档 P2 fallback 的重要修正
P2 与 P4/P3 一样，属于允许在 P1 保持不变时按优先级进行处理的运行约束；专利不是“P4/P3 后直接跳到只最小化 P2 违反”。正确顺序必须先尝试**P2 的分级最小松弛**。  
只有 P2、P3、P4 都达到最大允许松弛且联合可行集仍为空时，才进入最终“P1-safe + 运行约束违反程度最小”的联合动作选择。  
如果当前代码枚举名仍叫 `p2_fallback`，可以保留名称兼容旧接口，但其算法语义必须满足上述顺序；更推荐区分：

normal
p4_relaxed
p3_relaxed
p2_relaxed
min_violation_fallback


### 9.4 “最小松弛”如何搜索
【专利未规定】专利没有限定使用固定步长、二分搜索、网格搜索还是优化器，只限定：
1. 不超过最大松弛范围；
2. 只松到恢复至少一条完整可行路径的最小程度；
3. 每次判断都应基于完整的 S201→S202→S203 结果，而不是单库非空。
因此仓库可选择确定性的搜索实现，但必须在测试中验证“首次恢复即停止”。

### 9.5 最终最小违反联合动作
【专利规定】P2/P3/P4 均到最大允许松弛仍为空时，在满足 P1 的候选联合动作中选择运行约束违反程度最小的联合动作，并记录违反量。  
【专利未规定】不同运行约束之间如何归一化、加权、聚合成一个可比较标量，没有给出具体公式。仓库若需要实现，必须在配置/代码中显式定义并标注为“工程实现”，不能声称该标量化方式由专利规定。  
【实现约束】若连 P1-safe 候选联合动作都不存在，专利没有提供继续放宽 P1 的机制。代码必须将其视为硬不可行/紧急异常，不能把 mask 改成全 1。

### 9.6 `SafetyRecoveryResult` 建议语义
若仓库继续使用 `SafetyRecoveryResult`，至少应能提供：
```text
mode
effective_constraint_context
root_safe_mask
conditional_safe_masks / compatible-extendable structure
relaxation_details
forced_joint_action          # 仅最终 fallback 确实返回单一联合动作时
recorded_operational_violation
```
字段名可随真实代码调整，但信息语义必须完整。

## 10. S4：按水流方向进行条件动作选择
### 10.1 固定采样顺序
真实行为采样必须遵循：
```text
WDD → BHT → XLD → XJB → THR
```
不能让五个 Actor 在同一固定 observation 条件下并行独立采样，因为下游当前入流、decision observation 和当前可选动作集合依赖直接上游**本时刻已经选出的实际动作**。

### 10.2 掩码策略分布
令第 \(i\) 个 Actor 基于当前 \(o^{dec}_{i,t}\) 输出动作偏好 \(z_{i,t}(a_i)\)，当前实际动作掩码为 \(M_{i,t}(a_i)\)。策略：
\[
\pi_{\theta_i}(a_i\mid o^{dec}_{i,t},M_{i,t})
=
\begin{cases}
\dfrac{\exp(z_{i,t}(a_i))}
{\sum_{d:M_{i,t}(d)=1}\exp(z_{i,t}(d))},
&M_{i,t}(a_i)=1\\
0,&M_{i,t}(a_i)=0
\end{cases}
\]
实现中应优先对 invalid logits 使用稳定 masked-logit 处理，再进行 categorical sampling；最终概率语义必须与上式一致。

### 10.3 S401：最上游动作
WDD：
```text
输入：o_dec_WDD = o_base_WDD
mask：root safe mask
Actor：π_WDD(a | o_dec, mask)
输出：a_WDD,t
得到：Q_exec_WDD,t
```
如果 `root safe mask` 在 S3 后仍全 0，应视为实现错误或 P1 硬不可行状态，不能继续随机采样。

### 10.4 S402：直接下游动作
对 BHT：
\[
I_{BHT,t}=Q^{exec}_{WDD,t}+I^{int}_{BHT,t}
\]
构造：
\[
o^{dec}_{BHT,t}=(o^{base}_{BHT,t},I_{BHT,t})
\]
当前 mask 只能来自：
```text
与已选 WDD 动作兼容
AND
BHT 动作仍具有下游可延拓性
```
然后 BHT Actor 在该 mask 内采样。XLD、XJB 同理；THR 只需与已选 XJB 动作兼容。

### 10.5 S403：形成联合动作并保存真实行为条件
最终：
\[
a_t=(a_{1,t},a_{2,t},\ldots,a_{N,t})
\]
对每个智能体必须保存其**真实动作采样当时**的：
\[
o^{dec}_{i,t},\quad M_{i,t},\quad a_{i,t},\quad \log p^{old}_{i,t}
\]
这些量不是“下一时刻输入”，而是当前 \(t\) 的行为条件。

### 10.6 联合动作执行
环境执行联合动作后：
1. 用实际入流、实际总下泄做水量平衡；
2. 更新库容、水位；
3. 计算过机流量、出力、发电量；
4. 计算系统发电奖励；
5. 计算各实际存在长期运行约束的原始违反量；
6. 保存下一时刻状态；
7. 将 reward、constraint raw violation、active flag 与当前行为轨迹一起交给训练链路。

## 11. 长期运行约束原始违反量
【专利规定】长期约束按具体“水库—约束类型”分别建立。未承担某项任务的水库不建立该约束。

### 11.1 生态下泄
若生态下泄要求为 \(Q_i^{eco}\)：
\[
\xi^{eco}_{i,t}
=
\sqrt{
\max\left(
0,
\frac{Q_i^{eco}-Q^{exec}_{i,t}}{Q_i^{eco}}
\right)}
\]

### 11.2 保证出力
若保证出力要求为 \(P_i^{gua}\)：
\[
\xi^{gua}_{i,t}
=
\sqrt{
\max\left(
0,
\frac{P_i^{gua}-P_{i,t}}{P_i^{gua}}
\right)}
\]

### 11.3 航运下泄
若航运下泄要求为 \(Q_i^{nav}\)：
\[
\xi^{nav}_{i,t}
=
\sqrt{
\max\left(
0,
\frac{Q_i^{nav}-Q^{exec}_{i,t}}{Q_i^{nav}}
\right)}
\]
平方根：提高约束边界附近小幅违反的区分度，并压缩严重违反样本之间的数值差异，降低极端违反对约束价值学习的过度主导。

### 11.4 统一长期约束索引
每一个实际存在的“水库—约束类型”组合定义为一项约束：
\[
\mathcal J=\{1,2,\ldots,K\}
\]
例如：
```text
WDD-生态
BHT-生态
BHT-保证出力
XJB-航运
...
```
是否实际存在必须来自任务定义、数据或配置，不能由 AI 自行补齐。

## 12. 长期约束生效指标、归一化、容忍阈值与训练 cost
第 \(j\) 项约束生效指标：
\[
\chi_{j,t}\in\{0,1\}
\]
其中：
```text
χ_j,t = 1：该约束当前时刻实际生效
χ_j,t = 0：该约束当前时刻不生效
```
对只在特定季节或运行阶段生效的要求，必须根据当前运行阶段计算 \(\chi\)。

### 12.1 原始违反量到训练约束代价
第 \(j\) 项原始违反量为 \(\xi_{j,t}\)，固定归一化尺度为 \(z_j\)：
\[
c_{j,t}=\frac{\xi_{j,t}}{z_j}
\]
容忍阈值为 \(\epsilon_j^{tol}\)，实际用于约束价值估计和策略优化的约束代价：
\[
v_{j,t}
=
\chi_{j,t}
\max\left\{0,c_{j,t}-\epsilon_j^{tol}\right\}
\]
因此：
```text
raw violation = ξ
normalized violation = c = ξ / z
training constraint cost = v = χ * max(0, c - ε_tol)
```
仓库变量命名可以不同，但不能混淆这三层含义。

### 12.2 ConstraintBuffer 至少需要保存
```text
v[j,t]                  # 实际用于 constraint critic 的 cost
active_flag[j,t]        # χ_j,t
raw_violation[j,t]      # ξ_j,t，建议保留，便于论文统计与调试
```
同时每项约束独立拥有：
```text
constraint_id
normalization z_j
tolerance epsilon_tol_j
budget d_j
lambda_j
lambda_lr eta_lambda_j
```
若项目数据中没有可靠参数，不能自行创造。

## 13. Centralized Critic 与全局信息
【专利规定】各水库独立 Actor，设置集中式 Critic。Critic 的输入必须是**当前联合动作采样前已经获得的全局信息**。专利示例将各水库 base observation 组合为：
\[
x_t=
[o^{base}_{1,t},o^{base}_{2,t},\ldots,o^{base}_{N,t}]
\]
Critic 输出：
\[
V_\phi^R(x_t)
\]
以及：
\[
V_\phi^{C_1}(x_t),\ldots,V_\phi^{C_K}(x_t)
\]
即一个 Reward Value 和每条实际长期约束各自独立的 Constraint Value。

### 13.1 当前仓库 centralized state
【仓库实现】若每库 base observation 为 17 维：
\[
\dim(x_t)=5\times17=85
\]
所以当前：
```text
share_observation = 85
```
必须保持：
```text
prepare_step 生成的 x_t
==
Reward Critic buffer 在 t 使用的 x_t
==
所有 Constraint Critic buffer 在 t 使用的 x_t
```
**不能**在 BHT/XLD/... 顺序采样过程中用已经拼入当前实际入流的下游 `o_dec` 动态改写当前 \(x_t\)，否则它就不再是“联合动作采样前的全局信息”。

## 14. Reward/Constraint GAE 与 Lagrangian Advantage
### 14.1 Reward TD error
\[
\delta_t^R
=
r_t+\gamma V_\phi^R(x_{t+1})-V_\phi^R(x_t)
\]
Reward GAE：
\[
A_t^R
=
\sum_{l=0}^{T-t-1}
(\gamma\lambda_{GAE})^l\delta_{t+l}^R
\]

### 14.2 Constraint TD error
对第 \(j\) 项约束：
\[
\delta_t^{C_j}
=
v_{j,t}
+\gamma V_\phi^{C_j}(x_{t+1})
-V_\phi^{C_j}(x_t)
\]
Constraint GAE：
\[
A_t^{C_j}
=
\sum_{l=0}^{T-t-1}
(\gamma\lambda_{GAE})^l
\delta_{t+l}^{C_j}
\]

### 14.3 Lagrangian Advantage
在当前一轮 Actor 参数更新过程中固定所有长期约束乘子：
\[
A_t^L
=
A_t^R-\sum_{j=1}^{K}\lambda_jA_t^{C_j}
\]
实现中建议在进入一轮 HAPPO Actor 更新前显式保存：
```text
lambda_snapshot = current_lambdas.copy()
```
该轮所有 Actor 都使用同一组 snapshot，不允许更新第 2/3/4 个 Actor 时中途改变 \(\lambda\)。

### 14.4 Critic value target
专利给出：
\[
\hat V_t^R=A_t^R+V_\phi^R(x_t)
\]
\[
\hat V_t^{C_j}=A_t^{C_j}+V_\phi^{C_j}(x_t)
\]
Reward Critic 和 Constraint Critics 应分别基于各自目标更新。

## 15. 行为轨迹一致性：S4 与 S5 的核心接口
由于下游：

上游动作
→ 实际入流
→ o_dec
→ conditional mask
→ 下游动作

所以联合策略不是“五个 Actor 在同一固定观测下的简单独立乘积”，而是沿采样顺序形成的条件概率乘积：
\[
\pi_\theta(a_t)
=
\pi_{\theta_1}(a_{1,t}\mid o^{dec}_{1,t},M_{1,t})
\prod_{i=2}^{N}
\pi_{\theta_i}(a_{i,t}\mid o^{dec}_{i,t},M_{i,t})
\]
训练时**不得重新生成**下游 observation 和 mask，而必须直接使用行为采样阶段存下来的：
\[
(o^{dec}_{i,t},M_{i,t},a_{i,t})
\]
以及旧策略 log-prob。

### 15.1 ActorBuffer 时间索引不变量
同一个 buffer index \(t\) 必须对应：
```text
o_dec[t]
mask[t]
action[t]
old_log_prob[t]
```
不能：
```text
action/log_prob 写 t
o_dec/mask 写 t+1
```
否则后续 probability ratio 的分子与分母不再基于同一行为条件。

## 16. HAPPO：随机参数更新顺序与累计概率比
### 16.1 两种顺序绝不能混淆
真实水力行为采样顺序：
```text
WDD → BHT → XLD → XJB → THR
```
HAPPO 参数更新顺序：
```text
每轮随机生成 σ = (σ1, σ2, ..., σN)
```
前者由物理水力因果决定；后者是训练算法更新顺序，两者相互独立。

### 16.2 单个 Agent 新旧策略比
对第 \(i\) 个智能体，使用行为轨迹中保存的**同一个** \(o^{dec}_{i,t}\)、\(M_{i,t}\)、\(a_{i,t}\)：
\[
\rho_{i,t}
=
\frac{
\pi_{\theta_i}(a_{i,t}\mid o^{dec}_{i,t},M_{i,t})
}{
\pi_{\theta_i^{old}}(a_{i,t}\mid o^{dec}_{i,t},M_{i,t})
}
\]

### 16.3 累计已更新 Agent 的 ratio
随机更新顺序：
\[
\sigma=(\sigma_1,\ldots,\sigma_N)
\]
初始化：
\[
\mu_{0,t}=1
\]
准备更新顺序中第 \(m\) 个 Agent \(\sigma_m\) 时：
\[
\mu_{m-1,t}
=
\prod_{p=1}^{m-1}\rho_{\sigma_p,t}
\]
这里使用的是前面已完成更新 Agent 在更新后策略下重新计算得到的最终 new/old ratio。

### 16.4 当前 Agent 的 HAPPO surrogate
专利语义：
\[
L_{\sigma_m}^{actor}
=
\mathbb E_t
\left[
\min\left(
\rho_{\sigma_m,t}\mu_{m-1,t}A_t^L,\;
\operatorname{clip}(\rho_{\sigma_m,t},1-\epsilon,1+\epsilon)
\mu_{m-1,t}A_t^L
\right)
\right]
\]
若代码按最小化 loss 实现，可取该目标的相反数；不得改变数学语义。

### 16.5 每个 Agent 更新完成后的动作
当前 \(\sigma_m\) 更新完成后必须：
1. 在原轨迹保存的同一个 \(o^{dec}\)、mask、action 条件下重新计算更新后策略的 new/old ratio；
2. 将该最终 ratio 乘入当前累计 \(\mu\)；
3. 将新的累计 ratio 作为固定量传给下一个 Agent；
4. 直到全部 Actor 完成一次 HAPPO 更新。
HAPPO 不能退化为“随机顺序分别对五个 Agent 独立执行一次 PPO”。

## 17. 拉格朗日乘子更新
### 17.1 只统计实际生效时段
对于当前训练批次 \(\mathcal B\)，若第 \(j\) 项约束存在生效样本，专利使用折扣加权平均约束代价：
\[
\hat J_j
=
\frac{
\sum_{t\in\mathcal B}\gamma^t v_{j,t}
}{
\sum_{t\in\mathcal B}\gamma^t\chi_{j,t}
}
\]
因为 \(v_{j,t}\) 已包含 \(\chi_{j,t}\)，分子不能再重复乘一次 active flag。

### 17.2 乘子更新
\[
\lambda_j
\leftarrow
\left[
\lambda_j
+\eta_{\lambda_j}(\hat J_j-d_j)
\right]^+
\]
其中：
\[
[x]^+=\max(0,x)
\]
解释：
```text
J_hat_j > d_j → 增大 λ_j，后续更重视该约束
J_hat_j < d_j → 减小 λ_j，降低该约束压力
```

### 17.3 整个 batch 未生效
若：
\[
\sum_{t\in\mathcal B}\chi_{j,t}=0
\]
则：
```text
不计算 J_hat_j
不更新 λ_j
λ_j 保持原值
```
绝不能把“未生效”当成“有效的零违规样本”，否则会人为降低该约束的乘子。

## 19. 一次完整训练批次
```python
# 1. rollout 完成后，按专利定义构造各长期约束训练 cost
for j in constraints:
    c[j] = xi[j] / z[j]
    v[j] = chi[j] * max(0, c[j] - eps_tol[j])

# 2. Reward/Constraint Critics 计算 TD 与 GAE
A_R = reward_gae(...)
A_C[j] = constraint_gae(v[j], ...)

# 3. 当前 Actor 更新轮固定 lambda
lambda_snapshot = lambda_current.copy()
A_L = A_R - sum(lambda_snapshot[j] * A_C[j] for j in constraints)

# 4. 更新 Critics
update_reward_critic(...)
for j in constraints:
    update_constraint_critic(j, ...)

# 5. HAPPO：随机 agent 顺序
sigma = random_permutation(num_agents)
mu = ones_like(A_L)
for agent in sigma:
    rho = ratio_from_stored_behavior_condition(agent)
    update_actor_with_happo(agent, rho, mu, A_L)
    rho_final = recompute_ratio_after_update(agent)
    mu = mu * rho_final.detach()

# 6. Actor/Critic 当前轮完成后再更新各 λ
for j in constraints:
    if active_count(j) == 0:
        keep_lambda_unchanged(j)
    else:
        J_hat = discounted_active_period_mean(v[j], chi[j])
        lambda[j] = max(0, lambda[j] + eta_lambda[j] * (J_hat - d[j]))
```

## 21. `prepare_step → collect → env.step → insert → compute → train` 数据契约
### 21.1 `prepare_step`
应做到：
```text
读取当前物理状态与当日外部数据
构造全部 base observations
构造 pre-action centralized state x_t
运行正常 S2
必要时运行 S3
输出本决策步安全结构
不推进环境状态
```

### 21.2 `collect`
应做到：
```text
读取 prepare_step 结果
WDD→THR 顺序采样
每步基于实际上游动作重算下游实际入流
构造真实 o_dec
取与已选上游动作匹配的 conditional mask
保存实际行为 action / old_log_prob
```

### 21.3 `env.step`
只接受最终完整联合动作，执行真实物理 transition 并输出：
```text
next state
system reward
long-term raw violations ξ
active flags χ
diagnostics
```

### 21.4 `insert`
同一 \(t\) 对齐写入：
```text
per-agent:
  o_dec[t]
  action_mask[t]
  action[t]
  old_log_prob[t]

shared:
  x_t
  reward[t]
  ξ[j,t]
  χ[j,t]
```

### 21.5 `compute`
计算：
```text
v[j,t]
Reward GAE
Constraint GAEs
value targets
Lagrangian Advantage
```

### 21.6 `train`
执行：
```text
Reward Critic update
K Constraint Critic updates
随机 HAPPO agent order
preceding-agent ratio accumulation
Actor updates
最后更新各 λ
```

## 23. 必须长期保持的程序不变量
### 23.1 水力因果不变量
```text
上游动作确定
→ 上游 Q_exec 确定
→ 下游实际总入流确定
→ 下游 o_dec 确定
→ 下游 conditional mask 确定
→ 下游 Actor 采样
```

### 23.2 联合路径不变量
除专利最终最小违反 fallback 外，真正采样执行的联合动作必须位于当前 S2/S3 得到的完整可延拓路径中。

### 23.3 P1 不松弛
任何 recovery/fallback 不得主动突破 P1。

### 23.4 候选兼容性与真实执行一致性
当前：
```text
Q_exec == Q_target
```
若未来不再成立，必须整体重审 S202→S4 的一致性。

### 23.5 Critic 状态同步
```text
prepare_step x_t
==
Reward Critic share_obs[t]
==
所有 Constraint Critic share_obs[t]
```

### 23.6 行为轨迹同步
```text
o_dec[t]
mask[t]
action[t]
old_log_prob[t]
```
必须对应同一次真实行为采样。

### 23.7 首日不伪造历史
```text
previous_release_m3s = None
```
只关闭真正依赖该历史值的约束项。

### 23.8 长期约束激活不变量
```text
χ[j,t] = 1 → 才是第 j 项长期约束的有效生效样本
batch active_count[j] = 0 → λ_j 保持不变
```

### 23.9 HAPPO 累计 ratio 不变量
```text
已完成更新的 Agent
→ 在原行为 o_dec/mask/action 下重新计算 final new/old ratio
→ 累乘到 μ
→ μ 用于后续 Agent surrogate
```

### 23.10 `prepare_step` 无副作用
`prepare_step`、S201、S202、S203、S3 可行性搜索均不得提前推进库容、水位或上一时刻动作等环境物理状态。

## 30. 专利没有写死、仓库必须显式决定的内容
以下内容可以工程化选择，但必须在代码/配置/测试中透明：
1. \(\psi_i\) 的具体严格单调函数形式；
2. 每库动作数、map min/max；
3. observation 的具体数值编码和维数；
4. P2/P3/P4 的具体边界、最大允许松弛范围和松弛搜索算法；
5. 最终 fallback 中不同运行约束违反量的归一化/聚合规则；
6. \(E^{ref}\) 的具体固定尺度；
7. Critic/Actor 网络结构、隐藏层、RNN 与否；
8. batch size、GAE 参数、PPO clip、学习率；
9. 训练/评估时随机采样还是确定性选取（评估策略可不同，但安全 mask 逻辑不能变）；
10. 若未来引入河道传播时滞，应重新定义状态转移、下游入流与顺序决策关系，不能继续直接使用“上游当期下泄=下游当期入流组成”的当前模型。

## 31. 当前最重要的代码一致性风险
1. **S3 P2 语义风险：**若当前代码在 P4/P3 到最大后直接做 `p2_fallback`，而没有先按最大范围内最小必要程度放宽 P2，则与专利不一致。
2. **`Q_target/Q_exec` 风险：**当前假定二者相等；任何隐式裁剪都会破坏 S202 与 S4 的一致性。
3. **行为轨迹错位风险：**下游真实 `o_dec/mask` 若没有和当前 action/log_prob 同索引保存，HAPPO ratio 无效。
4. **Critic 时点风险：**centralized state 必须是联合动作采样前的全局信息，不得混入本步采样后才产生的动态条件。
5. **constraint active 风险：**未生效不能被统计成有效零 cost。
6. **HAPPO 退化风险：**随机顺序独立 PPO ≠ HAPPO，必须累计前序已更新 Agent 的 final ratio。
7. **候选入流污染环境风险：**S202 中的 candidate inflow 只能用于判断，不得推进真实状态。
8. **动作离散过粗风险：**连续物理可行区间非空并不保证离散动作集中有点落入；若频繁触发空集，需要检查动作网格，而不是放宽 P1。

## 32. 方法的一句话总结
> 本项目面向五库串联梯级水库日尺度多约束联合调度：先在当前决策步基于给定入流局部可行性、相邻候选动作兼容关系和由最下游向最上游的下游可延拓性构造完整梯级联合可行性动作掩码；若联合可行集为空，则保持 P1 绝对物理安全约束不变，严格按 P4→P3→P2 实施分级最小松弛，必要时在 P1-safe 联合动作中选择运行约束违反程度最小的动作；随后按 WDD→BHT→XLD→XJB→THR 的水流方向，根据上游实际下泄逐库更新下游实际入流、decision observation 和条件 mask 并采样动作；最后使用真实采样时保存的 observation/mask/action 条件，以集中式 Reward/Constraint Critics、Lagrangian Advantage、随机顺序 HAPPO 累计概率比和按实际生效时段更新的独立拉格朗日乘子完成长期策略优化。
